# Quality check against the 10 rules (2026-11-01)

Run on Windows 11 (Intel Core i7-13700H) with Python 3.14 in the repo's `.venv`. The Kafka and
PyFlink tests are skipped locally (no broker, no PyFlink wheel for Windows) and run in CI.
Mutations were applied one at a time by a script that restores each file.

| # | Rule | Status | Evidence |
|---|---|---|---|
| 1 | Assume every call can fail | pass | Kafka: `produce` flushes with a 30 s timeout and raises on undelivered messages or delivery errors; `consume` stops at a monotonic deadline and raises on consumer errors and tombstones (`kafka_io.py`). No swallowed exceptions in `src/`. A surviving mutant showed delivery errors were untested; a test now covers them. |
| 2 | Writes safe to retry | fixed | Kafka writes use `acks=all` and `enable.idempotence` (tested). `clickgen --out` wrote the file in place, so a crash left a partial file; it now writes a sibling `.tmp` file and renames it (`cli.py`), and a test re-runs it and checks the file is whole with no temp file left. |
| 3 | No race conditions | N/A | The engine and CLI are single-threaded; Flink parallelism is Flink's own, checked by the CI `flink` job. |
| 4 | Don't trust the clock | pass | Event time comes from the events; the watermark is derived from event timestamps, never the wall clock (`engine.py`). The consumer deadline uses `time.monotonic`. `time.time_ns()` only makes a unique consumer group id. |
| 5 | Read before changing | pass | The only env var, `KAFKA_BOOTSTRAP`, is documented in the README. Every doc link exists. |
| 6 | Never break compatibility | pass | Event JSON format unchanged; `from_json` still requires exactly the five fields. New `EventTimeEngine.open_windows` is additive. |
| 7 | One source of truth | pass | Window state names its invalidation: purged at the cleanup time (window end - 1 + allowed lateness), now asserted by a test. Python >=3.11 in `pyproject.toml`, CI and README. |
| 8 | Small changes, no secrets, validate input | fixed | Secret grep: nothing. Events are validated in `ClickEvent.from_json`. `clickgen` accepted `--events 0`, negative bounds, `--late-fraction` outside [0, 1], and a window that is not a multiple of the slide (a traceback); each is now an argparse error with exit 2. |
| 9 | Tests that can actually fail | fixed | No tautologies; the 4 skips state their reason (`-rs`). 7/10 mutants killed before, 10/10 after. |
| 10 | Re-verify | pass | Results below; CI on push (Kafka and Flink jobs included). |
