## Kafka and Flink jobs

The Kafka round trip and the three Flink comparisons run in the `kafka` and `flink` jobs. All three
jobs passed in [run 37644885338](https://github.com/EquinoxWN/streaming-feature-pipeline/actions/runs/37644885338)
(commit `c9b5d6e`): build 19 s, kafka 31 s, flink 1 min 14 s.

The Flink job's first CI runs exposed three problems, each fixed before that run:

1. PyFlink 2.3's window assigners take its own `Time` class, not `Duration`.
2. PyFlink pickles the job's functions with cloudpickle. Functions defined inside `run_flink`, and a
   typed side-output tag (whose nested field types keep Java handles), cannot be pickled; the
   functions now live in `flink_functions.py` and the late-data tag is untyped.
3. Python operators pass results downstream in bundles, so the events before a deliberate pause
   stayed in the bundle and the watermark never overtook the held-back event. When a pause is
   requested, the job now uses one element per bundle.

The Kafka round trip was also run once on the author's machine on 2026-10-07: the same pinned
`apache/kafka:4.3.1` image in Docker Engine 29.8.2 (temporary WSL 2 VM, removed afterwards, broker
limited to 1 GB), tests run from Windows with confluent-kafka 2 (librdkafka 2.16.0):
`pytest -m kafka` 1 passed in 7.4 s. PyFlink has no Windows wheels, so the Flink tests run in CI only.
